# Grand-V Relay 2.0 — Render (совместимый ретранслятор + диагностика)

**Важное предупреждение:** это обновление **не добавляет автомобили и анимации в оригинальный сайт `gta.zip.wf`**. Официальный клиент Grand-V имеет экспериментальный протокол 1. Он передаёт лишь тип `pose`: `seq`, `model`, `position`, `rotation`. Он не передаёт состояние машин, анимаций, пассажиров и предметов. В открытом GitHub-репозитории Grand-V опубликован код хостинга/лаунчера, но не исходники игрового движка, нужные для появления этих возможностей в игре.

Официальный серверный протокол: https://github.com/SebasKitten/Grand-V/blob/main/LauncherApp/rust/src/relay.rs

## Что реально сделано

- Сохранён совместимый с оригинальным GTA-клиентом путь `wss://.../relay` и протокол `1`.
- Комнаты на 2 игроков, проверка `RELAY_ACCESS_CODE`, `welcome`, `joined`, `pose`, `left`.
- Сохранение последней позиции. Вновь вошедший игрок сразу получает известную позицию других игроков, если они уже передавали `pose`.
- Новые счётчики количества принятых и пересланных пакетов координат.
- `/monitor` — удобная страница диагностики: сколько игроков в комнате и отправляет ли **каждый** клиент `pose`.
- `/diagnostic` — проверка подключения WebSocket и ключа, сохранена из предыдущей версии.
- **Отдельный** `wss://.../relay/v2` — прототип транспорта для **модифицированного** клиента: `player_state` (с анимацией, скоростью и привязкой к машине), `vehicle_state`, `vehicle_remove`, `object_spawn`, `object_remove`, состояние мира при подключении. Поддерживает до 8 клиентов в комнате. Клиент должен уметь обрабатывать эти пакеты и рисовать модельки сам. Оригинальная GTA **не подключается по `/relay/v2`** и не использует этот формат.
- Файл `examples/client_v2.js` — пример API транспорта для будущего клиентского патча, не готовая модификация GTA.
- Автоматические локальные тесты для обоих протоколов.

## Обновить свой Render без создания нового сервера

1. Распакуйте ZIP.
2. В своём GitHub-репозитории замените **`server.py`**, также обновите `requirements.txt`, при желании добавьте README, `examples`, `tests`.
3. Render → `gtavserver` → Manual Deploy → Deploy latest commit (или дождитесь автодеплоя).
4. Не меняйте существующую переменную `RELAY_ACCESS_CODE`.
5. Откройте https://gtavserver.onrender.com/health — версия должна быть `2.0-pose-inspection-and-v2-extension`.
6. В оригинальном лаунчере используйте **только** `wss://gtavserver.onrender.com/relay`, не `/relay/v2`.

## Диагностика невидимых игроков

1. На двух телефонах или ПК откройте `https://gta.zip.wf/launcher.html`.
2. У обоих: один и тот же **Relay address**, **Room name**, **Access code**, режим Sandbox и одна версия игры.
3. Запустите игру на обоих. Начните двигаться и поворачивать камеры.
4. На третьей вкладке откройте https://gtavserver.onrender.com/monitor.
5. Введите код `RELAY_ACCESS_CODE` из Render и название комнаты (не путайте с режимом `check`). Нажмите `Проверить движения` несколько раз.

**Интерпретация:**

- `players: 0` — в данной комнате нет игровых WebSocket-сессий. Возможно, игра подключилась к другому ретранслятору или другой комнате, или WebSocket отключился.
- `players: 1` — только одно устройство действительно вошло на этот сервер и в эту комнату.
- `players: 2`, у обоих `poses_sent_by_client: 0` — игры подключились, но не отправляют координаты; серверу нечего пересылать. Нужна отладка клиента.
- `players: 2`, счетчики `poses_sent_by_client` увеличиваются, и `relayed_to_other` растёт — **сервер передаёт позиции**. Если друг всё ещё невидим, проблема в создании/визуализации сетевых персонажей на стороне игрового клиента (или клиенту недоступны нужные модельные данные), а не в отсутствии пересылки сервером.
- `relayed_to_other: 0` при уже двух игроках и ненулевых `poses_sent_by_client` — возможная проблема с сервером; пришлите /monitor и Render Logs.

Сохраните в тайне `RELAY_ACCESS_CODE`. Форма `/monitor` отправляет ключ POST-запросом и не выводит его в ответе, но не передавайте скриншот с открытым вводом ключа.

## Расширение протокола 2 (не для обычного сайта GTA)

Отдельная точка подключения: `wss://gtavserver.onrender.com/relay/v2`.

Пример входа:

```json
{"type":"join","protocol":2,"key":"ВАШ_КОД","room":"DanilaServer","build":"modified-client-v1","map":"gta5"}
```

После подтверждения сервер отправит `world_snapshot` с ID, массивом участников и словарями `players`, `vehicles`, `objects`.

Пример движения:

```json
{"type":"player_state","seq":1,"model":1,"position":[0,0,0],"rotation":[0,0,0],"animation":"run","speed":3.5,"vehicle":null}
```

Пример машины:

```json
{"type":"vehicle_state","entity":"car_1","seq":1,"model":101,"position":[0,0,0],"rotation":[0,0,0],"velocity":[0,0,0]}
```

**Это транспорт состояния, а не физический игровой движок.** В клиенте понадобятся игровые функции: получить текущую позицию/состояние персонажа, создать удалённого персонажа, назначить анимацию, создать машину, обновить положение и анимацию машины, корректно посадить пассажира и удалять сущности. Они не доступны через стандартный браузерный WebSocket API без доступа к коду игры.

Ограничения прототипа v2: одна инстанция Render, без базы данных/постоянного мира; при перезапуске Render всё состояние исчезает. Нет авторитетной серверной физики и интерполяции, поэтому клиент должен реализовать сглаживание движения. Владение объектами ограничено соединением игрока; при его выходе объект/машина удаляются.

## Безопасность

Проект не содержит файлов GTA V, Rockstar и другого контента игры. Не публикуйте код доступа в публичном репозитории. Настройте один процесс сервера: комнаты хранятся в памяти процесса и не разделяются между репликами.
